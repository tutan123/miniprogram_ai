# 安全加固文档

## 概述

本文档说明了系统中实施的安全措施，用于防止刷积分、利用前端 bug 等安全问题。

## 数据库层安全

### 1. 唯一约束防止重复打卡
- **位置**: `Record` 模型
- **约束**: `@@unique([userId, taskId, checkinDate])`
- **作用**: 防止同一用户在同一任务同一天重复打卡
- **优势**: 数据库级别约束，即使并发请求也无法绕过

### 2. 积分校验
- **位置**: `User.points` 字段
- **验证**: 确保积分不为负数
- **实现**: 在更新积分时进行双重校验（事务内外）

### 3. 服务器时间验证
- **字段**: `Record.checkinDate` (格式: YYYY-MM-DD)
- **作用**: 使用服务器时间而非客户端时间，防止修改系统时间绕过限制

## 后端 API 安全

### 1. 打卡 API (`/api/task/complete`)

#### 安全措施：
- ✅ **服务器时间验证**: 使用服务器时间判断"今天"，不受客户端时间影响
- ✅ **频率限制**: 每分钟最多 10 次请求（防止快速重复调用）
- ✅ **唯一约束**: 数据库唯一约束防止并发重复打卡
- ✅ **位置验证**: 验证 GPS 坐标范围，确保在目标区域内
- ✅ **任务状态检查**: 只允许激活的任务打卡
- ✅ **积分范围验证**: 验证奖励积分在合理范围内 (0-1000)

#### 防止的攻击：
- ❌ 修改系统时间后重复打卡
- ❌ 快速连续调用 API 刷积分
- ❌ 并发请求导致重复奖励
- ❌ 伪造 GPS 坐标（需要精确位置）

### 2. 兑换 API (`/api/shop/exchange`)

#### 安全措施：
- ✅ **商品状态验证**: 只允许兑换 `status = 'active'` 的商品
- ✅ **频率限制**: 10 秒内最多 3 次请求
- ✅ **并发控制**: 事务中重新查询最新数据，防止并发时库存超卖
- ✅ **双重积分校验**: 事务前后都验证积分是否足够
- ✅ **价格验证**: 验证商品价格在合理范围内 (0-10000)

#### 防止的攻击：
- ❌ 兑换已下架商品
- ❌ 快速重复兑换
- ❌ 并发请求导致库存超卖
- ❌ 积分负数问题

### 3. 任务列表 API (`/api/tasks`)

#### 安全措施：
- ✅ **服务器时间**: 使用服务器时间判断任务完成状态
- ✅ **只显示激活任务**: 过滤 `isActive = true` 的任务

## 小程序前端安全

### 1. 防重复提交
- **位置**: `pages/checkin/checkin.js`
- **实现**: `isSubmitting` 标志位
- **作用**: 防止用户快速点击导致重复请求

### 2. 移除客户端时间判断
- **说明**: 所有时间相关判断都在服务器端完成
- **好处**: 客户端无法通过修改系统时间绕过限制

### 3. 错误处理
- **频率限制**: 识别 429 状态码，友好提示用户
- **网络错误**: 完善的错误处理和用户提示

## 安全建议

### 生产环境额外措施

1. **使用 Redis 实现分布式频率限制**
   - 当前实现使用内存 Map，单机有效
   - 生产环境应使用 Redis

2. **添加请求签名验证**
   - 小程序可以使用 AppSecret 签名
   - 防止直接调用 API

3. **日志和监控**
   - 记录所有积分变动操作
   - 监控异常请求（高频、异常坐标等）

4. **HTTPS 强制**
   - 小程序必须使用 HTTPS
   - 防止中间人攻击

5. **数据库备份**
   - 定期备份数据库
   - 防止数据丢失

## 已知限制

1. **频率限制**: 当前使用内存缓存，重启后重置
   - 生产环境建议使用 Redis

2. **GPS 验证**: 只能验证位置范围，无法防止模拟器/虚拟机
   - 可考虑添加设备指纹验证

3. **时区**: 固定使用 UTC+8（中国时区）
   - 如需国际化，需要动态时区配置
